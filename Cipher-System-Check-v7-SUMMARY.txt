## Technical Architecture

### v7 Core Script Flow

```
1. Validate Administrator access
2. Initialize logging to LocalAppData\CipherCheck\Logs\
3. Capture System Snapshot (OS, CPU, BIOS, GPU, volumes)
4. Run Windows Integrity Checks (SFC, DISM)
5. Deep SSD Analysis
   └─ Physical disk inventory
   └─ Storage reliability counters (SMART)
   └─ Drive health per device
6. Disk Checks (chkdsk, fsutil)
7. Event Log Analysis (30-day history)
   ├─ WHEA errors (memory/CPU/firmware)
   ├─ TDR events (GPU timeouts)
   ├─ Storage timeouts (controller issues)
   └─ Reboot/crash events
8. Driver & Firmware Analysis
   ├─ Signed drivers inventory
   ├─ Hotfixes/updates list
   ├─ GPU driver age
   └─ BIOS age
9. Performance Snapshot (top CPU/memory processes)
10. Diagnostic Scoring
    └─ Weighted points per category
11. Ranked Report Generation
12. Optional Repairs (if flags set)
13. Export Results (CSV, XML, TXT)
```

## Code Optimizations Made

### 1. **Eliminated Repetition**
```powershell
# v6: Three separate functions
function Write-Section { ... }
function Save-Text { ... }
function Invoke-Cmd { ... }

# v7: Same but with parameter docs and better names
# Plus added new functions:
function Get-SSDHealthDetail { ... }
function Get-WHEADetails { ... }
function Get-TDREvents { ... }
```

### 2. **Improved Error Handling**
```powershell
# v6: $ErrorActionPreference = 'SilentlyContinue' (hides everything)

# v7: More granular
try {
    $result = Get-StorageReliabilityCounter -PhysicalDisk $disk
    if ($result) { $diskInfo.Temperature = $result.Temperature }
} catch { 
    # Log error internally, continue gracefully
}
```

### 3. **Dynamic Volume Scanning**
```powershell
# v6: Hardcoded
Invoke-Cmd 'chkdsk C: /scan'
Invoke-Cmd 'chkdsk D: /scan'

# v7: Works with any drive count
$fixedDriveLetters = $vols | Where-Object { $_.DriveType -eq 'Fixed' -and $_.DriveLetter } | 
    Select-Object -ExpandProperty DriveLetter -Unique
foreach ($driveLetter in $fixedDriveLetters) {
    Invoke-Cmd ("chkdsk {0}: /scan" -f $driveLetter) ...
}
```

### 4. **Better Data Types**
```powershell
# v6: Mixed string/object outputs

# v7: Structured objects for each event type
$ssdHealth = @{
    FriendlyName = "Samsung 980 Pro"
    Temperature = "42°C"
    Wear = "5%"
    ReadErrors = 0
    WriteErrors = 0
}
```

### 5. **XML Export**
```powershell
# v6: Only CSV/TXT (hard to machine-read)

# v7: Also exports complete results as XML
$results | Export-Clixml 'diagnostic_results.xml'

# GUI loads this with:
$results = Import-Clixml $xmlPath
```

## Support & Troubleshooting

### File Location Issues
All files must be in the same directory (the folder where you saved the scripts). Example layout:
```
<scripts-folder>
├─ Cipher-System-Check-v7-Launcher.bat
├─ Cipher-System-Check-v7-GUI.ps1
├─ Cipher-System-Check-v7-Core.ps1
└─ Cipher-System-Check-v7-README.md
```

### GUI Won't Open
```powershell
# Check .NET Framework
reg query "HKLM\SOFTWARE\Microsoft\.NETFramework\v4.0.30319" /v Release
# Need 528040 or higher (4.8+)

# Manual WPF test
Add-Type -AssemblyName PresentationFramework
```

### Diagnostics Hang
- Event logs are large: wait 20+ minutes or clear old logs
- To clear safely:
  ```powershell
  wevtutil cl System /y
  ```

### Repairs Failed
- Ensure Administrator (Run as Administrator)
- Some repairs need UAC bypass:
  ```powershell
  powershell.exe -WindowStyle Hidden -ExecutionPolicy Bypass -File "...\Cipher-System-Check-v7-Core.ps1" -RunRepair
  ```

## Questions Before Running?

**Q: Will this delete my files?**
A: No. Diagnostics are read-only. Repairs use standard Windows maintenance tools (SFC, DISM, network resets). No data is deleted.

**Q: Do I need internet?**
A: No. All diagnostics are local. Logs save to your Desktop.

**Q: Can I run this monthly?**
A: Yes. Create a scheduled task for weekly checks. See README.md "Advanced Usage" section.

**Q: What if I run repairs incorrectly?**
A: Memory Diagnostics and Full Defender Scan are the only actions that require restart. Everything else is reversible.
